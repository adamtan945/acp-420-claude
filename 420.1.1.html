420.1.1・Users, Project Roles, and Permissions 16%

使用者、角色與權限類型

JSM 的人分兩邊：佔授權、進 Jira 的內部使用者，以及免費、只走 portal 的外部使用者。分清楚誰是誰、誰設定哪一層權限，是這個 domain 的地基。

考試佔 16%
官方考綱原文（這一節會考的範圍）
  • Define external users and roles (customer, stakeholder, reporter, organization, request participant).定義外部使用者與角色：customer、stakeholder、reporter、organization、request participant
  • Define internal users and roles (agent, assignee, collaborator, watcher, project admin, Jira admin, org admin).定義內部使用者與角色：agent、assignee、collaborator、watcher、project admin、Jira admin、org admin
  • Distinguish among the types of JSM Cloud permissions (product access, global permissions, permission scheme, customer permissions, knowledge base permissions).分辨五種權限：product access、global、permission scheme、customer、KB

3 分鐘速覽

誰付費、誰免費、權限分五層

  1. Agent＝佔 JSM 授權在 Service Desk Team role；看 queue、回覆 customer、管 customer 與 organization。
  2. Collaborator＝有 Jira 授權但不是 agent也放在 Service Desk Team role；只能看、加 internal comment、加附件、記工時、watch。
  3. Customer＝免費從 portal、email、widget 提單；只看得到自己的（或被分享的）request。
  4. Request participant＝被分享 request 的人跟 reporter 收一樣的通知；仍受 issue security 限制。
  5. Organization＝customer 的群組可跨 service project 重複用；跟 Atlassian organization（admin 用的）是兩回事。
  6. 五種權限Product access → Global → Permission scheme → Customer permissions → KB permissions。
使用者

內部與外部使用者

角色類型佔授權能做什麼
Customer外部✗提單、追蹤自己的 request、留言、讀 KB、核准別人的 request、（允許時）分享 request
Request participant外部✗被分享的 request：看、留言、收通知（預設跟 reporter 一樣）
Organization外部（群組）✗成員可以把 request 分享給整個 organization、在 portal 搜尋 organization 的 request
Stakeholder外部／內部◐ Premium 以上不佔被加到 incident 後收進度更新；權限跟 customer 一樣
Agent內部✓Queue、回覆 customer（公開留言）、internal comment、管理 customer 與 organization、寫 KB
Collaborator內部✓ Jira 授權只能看、internal comment、附件、watch／vote、記工時；給它更多權限也不會生效
Project admin內部✓Agent 能做的全部＋設定 request type、queue、SLA、portal、報表
Jira admin內部✓Permission scheme、workflow、custom field 等全站設定；改 project key 與 category
Org admin內部—管理 Atlassian organization：使用者、產品存取、外部 customer 的帳號政策
Stakeholder 的授權

官方：Premium、Enterprise 方案的 stakeholder 不佔 agent 授權；Free、Standard 方案只有 agent 能被加成 incident 的 stakeholder。

Project roles

內建三個 role 與它們代表的人

Project role放誰permission scheme 怎麼授權
AdministratorsProject admin必須有 Administer Projects，以及其他 role 有的所有權限
Service Desk TeamAgent 與 collaborator必須有 Create、Browse、Edit、Schedule、Add comments、Create attachments
Service Desk CustomersCustomer不要直接授權給這個 role：customer 的權限要給 security type「Service Desk Customer - Portal Access」，它會讀這個 role 判斷誰是 customer
自訂 permission scheme 的規則

官方：權限要給 Administrators role、Service Desk Team role 與 Service Desk Customer - Portal Access。改成直接給 group 或個人，service project 的部分功能可能失效。

Customer 透過 Portal Access 拿到的權限：Create work items、Browse projects、Add comments、Create attachments，以及 Assign work items（隱藏的 Assignee 欄位才能在提單時自動指派）。

自我檢查：先在心裡回答，再點開對答案
Q1為什麼 customer 的權限不直接給 Service Desk Customers role？看答案
官方要求給 Service Desk Customer - Portal Access security type：它讓 customer 進 portal，但不能進 Jira。
本段必考
  • Customer 權限給 Portal Access security type，不給 role。
  • Agent 與 collaborator 都在 Service Desk Team role。
權限類型

JSM 的五種權限

權限類型誰設定決定什麼
Product accessOrg admin（或有 user access admin 權限的 site admin）誰是 JSM agent（佔授權）、誰是 Jira 使用者、誰只是 customer
Global permissionsJira admin全站能力，例如 Administer Jira、Browse users and groups、Share dashboards and filters
Permission schemeJira admin 編 scheme；project admin 管 role 成員Project 內能做什麼：Browse、Create、Edit、Transition、Assign…
Customer permissionsSite admin 設 Customer access；project admin 設 Channel access 與 Customer sharing誰能建帳號、誰能提單、customer 能分享給誰
Knowledge base permissionsProject admin（在 service project 設定）＋ Confluence space 權限誰能看 KB 文章（含匿名）、誰能寫
本段必考
  • Product access 決定授權；permission scheme 決定 project 內的動作。
  • Customer permissions 分兩層：site（customer access）＋project（channel access、sharing）。
易錯觀念

考題愛用的錯誤說法

Collaborator 只要權限給夠，就能回覆 customer。
Collaborator 只能 internal comment；官方明說給它更多權限也不會被支援。要公開回覆就要 JSM agent 授權。
官方來源
把 customer 的權限授權給 Service Desk Customers role 最標準。
要給 Service Desk Customer - Portal Access security type。
Role 只是用來辨識誰是 customer。
官方來源
Request participant 一定看得到被分享的 request。
Participant 仍受 issue security 限制；security level 只開給 reporter 時，participant 看不到。
官方來源
Customer organization 就是 admin.atlassian.com 的 organization。
兩者無關：customer organization 是 JSM 裡 customer 的群組；Atlassian organization 是集中管理使用者與產品存取的單位。
官方來源
Customer 會佔一個 JSM 授權。
Customer 免費；只有 agent 佔 JSM 授權。
