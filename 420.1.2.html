3 分鐘速覽

Site 決定能不能建帳號，project 決定誰能提單

  1. Customer access（site admin）Settings → Products → JSM → Customer access：允不允許 customer 自己建帳號、要不要登入。
  2. 匿名提單Allow customers to create accounts＋勾 Customers can access and send requests from the portal without logging in；project 的 Channel access 選 Open。
  3. Channel access（project admin）Open＝沿用 site 的設定；Restricted＝只有被 agent／admin 邀請進這個 project 的 customer。
  4. Chat 不受 channel access 限制Restricted 時，Slack、Teams 提單的人會被自動邀請進 project。
  5. Customer sharing決定 customer 在 portal 用 Share with 能找誰：同 organization、或同 project、或輸入 email。
  6. Detail fieldsCustomer 與 organization 的 detail fields 是全站共用（不是只在這個 project），最多 50 個；建好後只能改 label。

兩層設定

Site 的 customer access × project 的 channel access

想要的效果Site：Customer accessProject：Channel access
任何人（不用登入）都能看 help center、提單Allow customers to create accounts＋勾「without logging in」Open
Help center 公開，但只有被邀請的人能在這個 portal 提單Allow customers to create accountsRestricted
只有站上已有帳號的人能提單Don't allow customers to create accountsOpen
只有站上已有帳號、而且被加進這個 project 的人Don't allow customers to create accountsRestricted
匿名也要留 email

即使開了不用登入，customer 送 request 時仍要輸入 email；系統會替他建帳號，他之後要設密碼登入才能看自己的 request。

Don't allow 的副作用

選 Don't allow customers to create accounts 時，sign-up 連結會被停用，未知寄件者的 email request 也不會被處理；customer 必須先有帳號或由 agent／admin 建立。

Organizations

把 customer 分組

  • Organization 是 customer 的群組，可以加到多個 service project，不用每個 project 重加一次人。
  • 成員可以把 request 分享給整個 organization，也會收到 organization 的 request 通知、能在 help center 搜尋它們。
  • Agent 能不能新增／移除 organization 與成員：由 Jira admin 在 Product settings → JSM → Configuration → Organization management 決定（Yes, agents can…）。
  • Email domain 自動分組：organization 可加最多 10 個 email domain；之後新加入、email 相符的 customer 自動加入。加 domain 不影響既有 customer；移除 domain 也不會把人踢出去。
  • 從 organization 移除 customer，他就失去透過該 organization 取得的 project 存取。
本段必考
  • Organization 跨 project 共用。
  • Email domain 只影響之後新加入的 customer。

Detail fields

Customer 與 organization 的詳細資料欄位

項目規則
位置Service project → Customers → Customers／Organizations 分頁 → Manage details → Manage detail fields
誰能建Organization admin 與 Jira admin（organization detail fields：admins）
範圍全站：建、改、刪都會影響所有 customer（或所有 organization），不是只有目前 project
欄位類型Text、Single-select、Multi-select（各最多 50 個選項）、Email、URL、Date、Number、Phone number
上限最多 50 個 detail fields
編輯只能改 label，不能改類型
權限每個欄位可設誰能看、誰能改（Manage permissions）
用途讓 queue、SLA、dashboard 依 customer／organization 資料分流（例如 VIP 等級）

動手做

實作 Lab：讓路人不登入就能提單，再收回

約 30 分鐘Site admin（Customer access）＋project admin（Customer permissions）；你都有

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：親手組合 site 的 Customer access 與 HELP 的 Channel access，用無痕視窗與 Dan 驗證誰進得了 portal；再看 customer sharing、organization 的 email domain 與 detail fields。

這個 Lab 對應的考點

Channel access 的 Open＝沿用 site 的 customer access；匿名提單要 site 勾「without logging in」＋project 選 Open；Restricted 只讓被邀請的 customer 用 portal、email；email domain 只影響之後加入的 customer；detail fields 全站共用、只能改 label。

準備

  • 確認在環境頁的起點：Customer access 是 Allow customers to create accounts（不勾 without logging in）；HELP 的 Channel access 是 Open。
  • Cara 在 Acme Corp，Dan 不在任何 organization；兩人都是由你在 Customers 頁加進 HELP 的。

步驟

  1. 你應該看到：Don't allow customers to create accounts 與 Allow customers to create accounts；後者底下有一個勾選框 Customers can access and send requests from the portal without logging in。
  2. 你應該看到：Channel access 有 Open 與 Restricted；Customer sharing 有幾種搜尋範圍與關閉分享，下面另有 Sharing requests with organization。
  3. 你應該看到：要求登入（可以看到註冊連結）：site 允許建帳號，但沒勾不登入。
  4. 你應該看到：不用登入就看得到 help center 與 HELP 的 portal；打開一個 request type，表單上仍要填 email（送出時系統會替他建帳號）。不要送出，或用一個新的 email 別名送出。
  5. 你應該看到：路人不能再在 HELP 提單；Dan 仍可以（他是被 agent／admin 直接加進 HELP 的 customer）。
  6. 你應該看到：Dan 不在任何 organization，不能分享；Cara 只找得到 Acme Corp 裡的人。
  7. 你應該看到：Dan 沒有被加進 Acme Corp：加 domain 不影響既有 customer，只影響之後新加入的。
  8. 你應該看到：欄位出現在所有 customer 的資料上（全站，不只 HELP）；編輯時只能改 label，不能改類型。新站台若找不到 Manage details，這一步只看教材（見環境頁的「新站台沒有的功能」）。

試試看：改一個設定，觀察差異

T1Customer access 改成 Don't allow customers to create accounts，用一個從沒用過的 email 別名寄信到 HELP 的 email 地址。看結果
不會建立 request：未知寄件者的 email request 不會被處理，portal 的註冊連結也停用。做完改回 Allow。
T2Customer sharing 改成 Customers can search for other customers within their space or organizations，Dan 再試著分享給 Cara。看結果
Dan 搜尋得到 Cara（同一個 project 的 customer）。要讓 customer 自己選 approver，就選這個。
T3（想像，不實際做）Channel access 是 Restricted 時，有人從 Slack 或 Teams 的 chat 提單。看結果
Chat 不受 channel access 限制，提單的人會被自動邀請進 project。
心像錨點：閉上眼睛想一次這個畫面

上下兩層開關：上層是 Customer access 那個「without logging in」勾選框，下層是 HELP 的 Open／Restricted。上層沒開，下層選 Open 也只是「沿用上層」。Site 管能不能建帳號，project 管能不能進門。

收尾

  • Customer access 改回起點：Allow customers to create accounts、不勾 without logging in。
  • HELP 的 Channel access 是 Open；Customer sharing 改回原本的選項。
  • 移除 Acme Corp 的 email domain（移除不會把人踢出 organization）。
  • 刪除 VIP level 欄位（欄位與資料會一起刪除；這是練習用欄位）。
