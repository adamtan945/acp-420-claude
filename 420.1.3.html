3 分鐘速覽

加人、指派與限制誰看得到

  1. 加 agentInvite team：輸入 email → 加進 Service Desk Team role。Project admin 只能加「已經有 JSM 授權」的人；全新的 agent 要 org admin。
  2. 加 collaborator把有 Jira 授權（無 JSM 授權）的人加進 Service Desk Team role。
  3. Role 成員 vs group 成員Project admin 能管 role 成員；group 成員只有 Administer Jira 才能改。
  4. Project lead 與 default assigneeProject admin 可改；default assignee 只能是 Unassigned 或 project lead。
  5. 指派的五種方式手動、project default assignee、component lead、request form 上預設（隱藏）的 Assignee、automation。
  6. Issue security 用 roleSecurity level 加 Service Desk Team role（或 reporter）就能只讓 agent 與提單人看到。
團隊成員

Agent、collaborator 與 role

  1. Invite teamService project 側欄 → Invite team → 輸入 email → Invite。被邀請的人進 Service Desk Team role。
  2. 誰能邀請誰Project admin：只能加已經有 JSM 授權的人（例如已是別的 project 的 agent）。Org admin：可以加任何人（新 agent 會佔新授權）。
  3. People and accessSpace settings → Access → People and access：把 user 或 group 加進 role，一個人可以在多個 role。
  4. 移除授權Jira admin：Settings → User management → 關掉 JSM 存取。授權釋放、從 jira-service-project user group 移除，所有 service project 都不能再當 agent。
Role 還是 group？

官方：group 成員只有 Administer Jira 能改，所以 project admin 通常偏好直接把使用者加進 project role。

Q1Project admin 想把一位從沒用過 JSM 的新同事加成 agent，Invite team 失敗。為什麼？看答案
Project admin 只能加已經有 JSM 授權的人；新 agent 要 org admin 先給產品存取（或由 org admin 邀請）。
Q2想讓開發人員只能在 request 留 internal comment，要把他加到哪個 role？看答案
Service Desk Team role（他沒有 JSM 授權，所以是 collaborator）。
本段必考
  • Agent 與 collaborator 都進 Service Desk Team role，差在有沒有 JSM 授權。
  • 新 agent 要 org admin。
指派

Request 會被指派給誰

方式在哪設適合
手動Queue 或 issue view 的 Assignee臨時分派、Assign to me
Project default assigneeSpace settings → Details沒有其他規則時的最後兜底；只能 Unassigned 或 project lead
Component leadComponents 設定（component 的 default assignee）依服務或模組分流
Request form 預設值Request type 的 Request form：加 Assignee 欄位、設預設值、勾 Hide from portal某種 request 固定給某人；customer 看不到也改不了
AutomationAutomation rule：Assign issue（含 balanced workload、round-robin）輪流指派、依條件指派
表單預設 Assignee 需要權限

官方：Service Desk Customer - Portal Access 必須有 Assign work items 權限，隱藏的 Assignee 欄位才能在 customer 提單時生效。

Q1Project lead 是 Mia，project admin 想把 default assignee 設成 Leo，做得到嗎？看答案
不行：default assignee 只能 Unassigned 或 project lead。要嘛把 project lead 改成 Leo，要嘛用 component lead、表單預設或 automation。
本段必考
  • Default assignee 只能 Unassigned 或 project lead。
  • 表單預設 Assignee＝隱藏欄位＋Portal Access 要有 Assign 權限。
Issue security

用 role 限制誰看得到 request

  • Issue security scheme（Jira admin 建）→ 定義 security level → 每個 level 加入「誰能看」：project role（例如 Service Desk Team）、Reporter、Assignee、group、user／group custom field。
  • 把 scheme 套到 service project 後，可以設 default security level，讓所有新 request 預設只有 agent 與 reporter 看得到。
  • Request participant 與 organization 成員也受 security level 限制：level 沒包含他們，他們就看不到。
  • 要讓 customer 提單後看得到自己的 request：level 要包含 Reporter（否則能建立卻看不到）。
考題長相

「HR 的 request 只有 HR agent 與提單人能看」→ 建 security level，成員放 HR agent 的 role（或 group）＋Reporter，設成該 project 的 default level。

本段必考
  • Security level 用 role＋Reporter 最常見。
  • Participant 也受 security level 限制。

為什麼他看不到、做不到

症狀先查
新同事看不到 queueProduct access：他有 JSM 授權嗎？在 Service Desk Team role 嗎？
Collaborator 無法回覆 customer正常：collaborator 只能 internal comment；要 agent 授權
Customer 進不了 portalChannel access 是 Restricted 而他沒被邀請？site 不允許建帳號而他沒帳號？
Customer 提單成功但看不到自己的 requestIssue security level 沒包含 Reporter
Participant 看不到被分享的 requestIssue security level 沒包含 participant（或 organization）
其他 Jira 使用者想看 service project 的 issueJira admin 在 permission scheme 把 Browse Projects 給 Application access → Any logged in user
其他 Jira 使用者想留言把 Add comments 給 Any logged in user；他們只能 internal comment，不能公開回覆
本段必考
  • 排查順序：產品存取 → role → permission scheme → customer permissions → issue security。
