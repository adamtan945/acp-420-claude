3 分鐘速覽

加人、指派與限制誰看得到

  1. 加 agentInvite team：輸入 email → 加進 Service Desk Team role。Project admin 只能加「已經有 JSM 授權」的人；全新的 agent 要 org admin。
  2. 加 collaborator把有 Jira 授權（無 JSM 授權）的人加進 Service Desk Team role。
  3. Role 成員 vs group 成員Project admin 能管 role 成員；group 成員只有 Administer Jira 才能改。
  4. Project lead 與 default assigneeProject admin 可改；default assignee 只能是 Unassigned 或 project lead。
  5. 指派的五種方式手動、project default assignee、component lead、request form 上預設（隱藏）的 Assignee、automation。
  6. Issue security 用 roleSecurity level 加 Service Desk Team role（或 reporter）就能只讓 agent 與提單人看到。

  • Add an agent to your service spaceOnly organization admins can add anyone (new and existing agents) to a service space.
  • Manage service project role membershipsSince group membership can only be edited by users with the Administer Jira global permission, project administrators may prefer to assign users, rather than groups, to their project roles.
  • Edit your service space detailsNote that the default assignee can only be either Unassigned or the Space lead.
  • Grant users access to security levels in a work item security schemeReporter - this grants access to anyone listed in a work item's Reporter field
團隊成員

Agent、collaborator 與 role

  1. Invite teamService project 側欄 → Invite team → 輸入 email → Invite。被邀請的人進 Service Desk Team role。
  2. 誰能邀請誰Project admin：只能加已經有 JSM 授權的人（例如已是別的 project 的 agent）。Org admin：可以加任何人（新 agent 會佔新授權）。
  3. People and accessSpace settings → Access → People and access：把 user 或 group 加進 role，一個人可以在多個 role。
  4. 移除授權Jira admin：Settings → User management → 關掉 JSM 存取。授權釋放、從 jira-service-project user group 移除，所有 service project 都不能再當 agent。
Role 還是 group？

官方：group 成員只有 Administer Jira 能改，所以 project admin 通常偏好直接把使用者加進 project role。

Issue security

用 role 限制誰看得到 request

  • Issue security scheme（Jira admin 建）→ 定義 security level → 每個 level 加入「誰能看」：project role（例如 Service Desk Team）、Reporter、Assignee、group、user／group custom field。
  • 把 scheme 套到 service project 後，可以設 default security level，讓所有新 request 預設只有 agent 與 reporter 看得到。
  • Request participant 與 organization 成員也受 security level 限制：level 沒包含他們，他們就看不到。
  • 要讓 customer 提單後看得到自己的 request：level 要包含 Reporter（否則能建立卻看不到）。
考題長相

「HR 的 request 只有 HR agent 與提單人能看」→ 建 security level，成員放 HR agent 的 role（或 group）＋Reporter，設成該 project 的 default level。

本段必考
  • Security level 用 role＋Reporter 最常見。
  • Participant 也受 security level 限制。
資料來源（5）有疑慮時點開看官方原文
  • What are work item security schemes?While permission schemes manage who can access a space, work item security schemes let you control who can see specific work items within that space.
  • Grant users access to security levels in a work item security schemeReporter - this grants access to anyone listed in a work item's Reporter field
  • Create a new work item security scheme and security levelsIf you'd like to apply this level to all work items in the spaces that use this scheme, select Default in the Actions column.
  • What are request participants?For example, if an administrator customizes requests so that only reporters can view them, then request participants won't be able to view the request.
  • Customize Jira Service Management permissionsOtherwise, customers might be able to create work items but not view them after they've been created.

動手做

實作 Lab：放人進 role、設預設指派、鎖住一張 request

約 30 分鐘Project admin（role、default assignee、request type）；Jira admin（issue security scheme）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：把 Kim 放進 Service Desk Team 當 collaborator、試 default assignee 與表單預設 Assignee，再用 issue security level 讓一張 request 只有 agent 與提單人看得到。

這個 Lab 對應的考點

Agent 與 collaborator 都進 Service Desk Team role，差在 JSM 授權；default assignee 只能 Unassigned 或 project lead；表單預設 Assignee＝隱藏欄位；security level 沒包含 Reporter，customer 就看不到自己的 request。

準備

  • 先把 Kim 從 HELP 的 Service Desk Team role 移除（步驟 1 會加回）。
  • HELP 有一張 Cara 提的 request（420.1.1 那張即可）。

步驟

  1. 你應該看到：Kim 出現在 Service Desk Team。這裡管的是 role 成員；group 成員只有 Jira admin 能改。
  2. 你應該看到：Kim 能看、能加 internal comment，沒有回覆 customer 的選項：她是 collaborator。
  3. 你應該看到：Default assignee 只有 Unassigned 與 Space lead（project lead）兩個選項，不能直接選 Leo。
  4. 你應該看到：通常會自動指派給 Leo：要讓某人當預設，就把他設成 project lead。
  5. 你應該看到：Cara 的表單上看不到 Assignee；新 request 指派給 Ana（表單預設優先於 project default assignee）。
  6. 你應該看到：HELP 已套用 HELP Security；Agents only 底下只有 Service Desk Team。
  7. 你應該看到：Cara 看不到自己提的這張 request；Leo、Kim（都在 Service Desk Team）仍看得到。
  8. 你應該看到：Cara 又看得到了。Security level 幾乎都要加 Reporter。

試試看：改一個設定，觀察差異

T1在這張 Agents only（含 Reporter）的 request 把 Dan 加成 request participant，Dan 打開 portal。看結果
Dan 看不到：participant 也受 issue security 限制，level 沒包含他就看不到。做完移除 Dan。
T2（想像，不實際做）Leo 只是 project admin、不是 org admin，用側欄 Invite team 邀一個從沒用過 JSM 的 email。看結果
加不進來：project admin 只能加已經有 JSM 授權的人；全新的 agent 要 org admin。
T3在 Space permissions 把 Browse Projects 加給 Application access → Any logged in user，請一位只有 Jira 存取、不在 HELP 任何 role 的人（或暫時把 Kim 移出 role）打開 HELP。看結果
他看得到 HELP 的 work item，但只能 internal comment（加了 Add comments 時），不能公開回覆。做完把 Any logged in user 移除、Kim 加回 role。
心像錨點：閉上眼睛想一次這個畫面

Space settings → Details 的 Default assignee 下拉選單：只有 Unassigned 和 Space lead 兩行。旁邊那張 request 的鎖頭：沒有 Reporter，Cara 打開自己的單是空的。

收尾

  • 把 Cara 的 request 的 security level 清空；HELP 改回不使用 work item security scheme。
  • Default assignee 改回 Unassigned、Space lead 改回你。
  • Request type 的 Request form 移除預設的 Assignee。
  • 確認 Kim 在 Service Desk Team role；Space permissions 沒有 Any logged in user。
