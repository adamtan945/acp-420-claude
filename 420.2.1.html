3 分鐘速覽

Queue＝給 agent 看的 JQL 清單

  1. Queue 是一種 filter依 request type、status、JQL 篩出 request；可設欄位與排序。
  2. Project admin 建立與編輯Queues 旁 More actions → Queue settings → Create new queue。
  3. Priority groups把 queue 分組給不同團隊；一個 queue 可屬於多個 group；沒進 group 的在「View all queues」（考綱稱 Other）。
  4. 會自動更新數字的只有 Starred 與 priority groupsView all queues 不刷新、預設收合；數字到 999 顯示 999+。
  5. SLA 函數排 queue"Time to first response" < remaining("2h")、breached()、paused()…
  6. 上限每個 service project、每個 work category 最多 300 個 queue。
建立

建立與排序 queue

  1. 建立Name → Priority group（可多選）→ Filter by（type、status、resolution、label…或切到 Advanced 寫 JQL）→ Order by → Columns 拖拉排序 → Create。
  2. 編輯Queue settings → 選 queue → More actions → Edit queue；改名稱、篩選、欄位時有即時預覽。
  3. 排序側欄Queue settings → Queues 分頁 → Reorder queues → 拖拉 → Done。
  4. 加 view每個 queue 預設是 list，可再加 board 或 calendar view。

Priority groups

把 queue 分給不同團隊

  • 一個 service project 有多個團隊時，用 priority group 讓每個團隊只看自己的 queue，例如「Emma's Work」「Design Team Requests」「L3 Urgent Escalations」。
  • Queue settings → Priority group 分頁 → Create group；再用 Manage queues 選 queue 與順序。
  • 一個 queue 可以屬於多個 priority group。
  • 沒被放進任何 group 的 queue 出現在側欄的 View all queues（考綱寫作「Other」）。
  • Agent 可以切換自己要看的 priority group。
  • Starred 與 priority group 內的 queue 會定期刷新數字；View all queues 不刷新、預設收合——把常用的 queue 放進 group 或 star 起來。
考題長相

「兩個團隊共用一個 service project，各自只想看自己的 queue」→ priority groups；「某 queue 的數字一直不更新」→ 它在 View all queues 裡。

本段必考
  • 一個 queue 可屬於多個 group。
  • 沒分組的在 View all queues（Other），不刷新。
JQL

Queue 常用的 JQL 與 SLA 函數

需求JQL
還沒解決的 incidentresolution = Unresolved AND "Request type" = "Report an incident"
2 小時內會違約（含已違約）"Time to resolution" < remaining("2h")
已違約（最後一個 cycle）"Time to first response" = breached()
曾經違約過"Time to resolution" = everBreached()
SLA 暫停中（等 customer）"Time to resolution" = paused()
等待首次回覆超過 30 分鐘"Time to first response" > elapsed("30m")
指派給我的assignee = currentUser() AND resolution = Unresolved
APAC 的 customerreporter in customerDetail("Region", "APAC")
Platinum 等級的 organizationorganizations in organizationDetail("Support level", "Platinum")
remaining() 的正負

remaining("2h") 同時抓「還剩不到 2 小時」與「已違約」的；只要未違約的，加 >= remaining("0h") 或 != breached()。

  • customerDetail／organizationDetail 只用 IN、NOT IN。
排查

Queue 出問題時

症狀原因與處理
Queue 數字不更新Queue 在 View all queues（不刷新）；放進 priority group 或 star
數字顯示 999+Queue 只算到 999；縮小範圍，例如加 updated >= -14d
Queue 顯示警告而不是數字篩選效能差；簡化 JQL（避免跨多個 custom field、label、Marketplace 函數）
用 summary ~ "fault" 分類很慢又不準改用 request type、隱藏欄位或 automation 加 component／label，再依分類建 queue
每個 agent 都建自己的 queue，拖慢大家用 currentUser() 建一個動態 queue，再請 agent star
該出現的 request 沒進 queue檢查 JQL（status、resolution、request type 寫錯）與 agent 的 issue security
本段必考
  • 多個簡單 queue 優於一個複雜 queue。
  • 個人 queue 用 currentUser()。
