3 分鐘速覽

SLA＝名稱＋條件＋目標＋calendar

  1. ConditionsStart（開始計時）、Pause（暫停，選填）、Stop（停止）；多個條件任一符合就生效。
  2. Goals每個 goal＝JQL（哪些 work item）＋time target＋calendar；由上而下比對，第一個符合的生效。
  3. Calendar時區、工作日、時段（可多段，例如扣掉午休）、假日；預設 09:00–17:00。
  4. Priority 分組Goal 下可加 priority，每個 priority 各自的 target；All remaining priorities 兜底；最多 90 個 goal。
  5. 名稱建好就不能改所以要取清楚的名字，例如 Time to first response。
  6. 新 SLA 套到所有 work item包含已關閉的；編輯後進行中的 cycle 會重算或被丟棄。

Goals

由上而下比對的目標

  • Space settings → Request management → SLAs → Add SLA（或 Edit）。
  • Goal 依清單由上而下比對 JQL，第一個符合的 goal 生效；最後一個 goal 通常是「All remaining work items」兜底。
  • 沒有任何 goal 符合的 work item 就沒有這個 SLA（queue 看不到時鐘）；兜底的 All remaining 設成 No target 時也一樣不會顯示。
  • 每個 SLA 最多 90 個 goal；在 goal 下用 Add priority 分組，每個 priority 各自的 target，仍只算 1 個 goal。All remaining priorities 會接住其他 priority（含 None）。
  • Priority 改變時，已計時間沿用、剩餘時間依新 priority 的目標重算，SLA 不會重新開始。
  • 不同區域或時區：用 custom field 分 goal，各 goal 選不同 calendar。
  • 可以用 customer／organization detail 寫 goal 的 JQL（例如 Platinum 客戶目標較短）。
避免

官方：同一個人同時是 reporter 與 assignee，SLA 可能算不準。Goal 下已用 priority 分組時，不要在 JQL 再寫 AND priority = …，會重複。

Calendar

工作時段

  1. 建立SLAs 頁右上 calendar 圖示 → Add calendar → 名稱與時區。
  2. 工作日與時段勾選工作日、每天加時段；按 ＋ 可在一天內加多段（例如午休前後）。
  3. 假日加入國定假日；假日不計時。
  4. 套用在 goal 的 Calendar 欄位選它。新建 calendar 時時段預設帶入 09:00–17:00；goal 若選 24/7 calendar 則全天候計時。
本段必考
  • Calendar 決定「什麼時候」算時間；pause 決定「什麼狀態」不算。

動手做

實作 Lab：做一個只算上班時間、會暫停的 SLA

約 30 分鐘Project admin（或 Jira admin）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：從零建一個 SLA：start、pause、stop 條件，兩個 goal，以及自訂的上班時段 calendar；再故意調整 goal，看哪一個生效。

這個 Lab 對應的考點

SLA＝conditions（start、pause 選填、stop）＋goals（JQL、target、calendar，由上而下第一個符合）＋calendar；名稱建立後不能改；新 SLA 套用到所有相關 work item（含已關閉）；priority 改變不會重新計時。

準備

  • HELP 的 workflow 有 Waiting for customer 一類的等待狀態（ITSM 範本通常有；名稱不同就用你看到的等待狀態）。

步驟

  1. 你應該看到：列出現有的 SLA（ITSM 範本通常有 Time to first response、Time to resolution）。
  2. 你應該看到：新 calendar 的時段預設帶入 09:00–17:00；一天可以有兩段（扣掉午休）。
  3. 你應該看到：名稱欄位在時鐘圖示旁，也可以選既有的名稱。這個名稱建立後就不能改，所以要一開始就取清楚。
  4. 你應該看到：三區分別是 start、pause、finish；pause 是選填，每區可以加多個條件，任一符合就生效。
  5. 你應該看到：Goal 清單由上而下：priority = Highest 在上，All remaining 在最下面兜底。
  6. 你應該看到：新 request 有 Lab first reply 在倒數（下班時間不扣）；通常舊 request 也套上了這個 SLA（新 SLA 會套用到所有相關 work item，含已關閉的）。
  7. 你應該看到：Lab first reply 顯示暫停，不再扣時間。
  8. 你應該看到：目標換成 1h，但已經計算的時間沿用，不會從頭計時；回覆 customer 後 SLA 停止，顯示達成。

試試看：改一個設定，觀察差異

T1在 priority = Highest 的下面加一個 goal："Request type" = "（你選的 request type）" → 2h。用這個 request type 提一張 Highest 的 request。看結果
目標是 1h，不是 2h：goal 由上而下比對，第一個符合的生效。把具體的 goal 往上移才會吃到 2h。
T2把 All remaining 的 target 改成 No target，再看一張 priority 不是 Highest 的 request。看結果
這張 request 上看不到 Lab first reply：沒有 goal 符合（或兜底沒有目標）就沒有這個 SLA。做完改回 8h。
T3在 Lab first reply 的第一個 goal 下按 Add priority，加 High → 4h。看結果
仍然只算 1 個 goal（上限 90 個）；All matching priorities 會變成 All remaining priorities，接住其他 priority（含 None）。
心像錨點：閉上眼睛想一次這個畫面

SLA 編輯頁：上半是三欄條件（Start、Pause、Finish），下半是由上而下的 goal 清單，每列右邊有 calendar 下拉。開、停、暫、目標、日曆；由上而下第一個。

  • Taipei office calendar 可以留著，或在 calendar 頁刪除。
