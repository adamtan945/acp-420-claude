Features 頁：要用什麼功能自己開

  1. 位置Space settings → Features：用開關啟用或停用功能。
  2. Board 與 calendar考綱寫在 Feature tab；現行 Cloud 改在 queue 上用 Add to navigation 加 board、calendar view（Jira admin 或 space admin）。
  3. Work categoriesService requests、Incidents、Problems、Changes、Post-incident reviews；決定側欄分區與 request type 分類。
  4. 方案限制Problem、Change、major incident、post-incident review 只有 Premium／Enterprise（2024/10/16 起）。
  5. Alerts、On-call 任何 project 都能開；Services 只有 ITSM project在非 ITSM project 開這些要 Jira admin。
  6. Feature labFeatures 頁最下方，試用尚未正式發布的功能。

Work categories

什麼時候開哪一種

Work category處理什麼什麼時候開
Service requests例行請求：申請權限、借設備、問問題幾乎都要；IT、HR、Facilities 都適用
Incidents服務中斷或品質下降，要盡快恢復有營運服務、需要 on-call 處理事故
Problems找出一再發生的 incident 的根本原因同類 incident 重複發生，要做根本原因分析（Premium 以上）
Changes要審核、排程、評估風險的變更部署、設定變更要 CAB 核准、需要 change calendar（Premium 以上）
Post-incident reviews事故後檢討重大事故後要留紀錄與改善項目（Premium 以上）
降級時不掉資料

官方：從 Premium 降到 Standard 時資料不會遺失；Changes、Problems、PIR 的 request type 變成 Unassigned，work item 移到 All queues。

Incident 協作

Alert 與 incident 的 priority、chat 工具

  • Alert priority：P1 Critical、P2 High、P3 Moderate、P4 Low、P5 Informational。Priority 提高時通知流程會重新開始。
  • 對應 incident priority：Space settings → Operations → Incident management → Assign alert priorities。預設前 5 個 incident priority 對應 P1–P5；新增的 incident priority 對應最低的 P5。這個對應由 Jira admin 在全域設定，會影響所有使用 incident management 的 project。
  • Responder alerts：有人被指派、被加成 responder、或是受影響服務的 owner 時會自動建 alert；建議把 Responders 欄位加進 incident 的 request type。
  • Chat 工具（incident 協作）：從 incident 建立 Slack／Teams 頻道、自動加入 responder、在頻道裡更新與摘要；屬於 Premium 的進階 incident 功能。
  • Chat 提單（另一件事）：在 Space settings → Channels & self service → Chat 設定，讓 customer 從 Slack／Teams 提單；Restricted channel access 也擋不住 chat 提單。
本段必考
  • Alert P1–P5；可以跟 incident priority 不同。
  • Priority 變高，通知流程重來。
資料來源（5）有疑慮時點開看官方原文
  • What are alert priorities?When the alert priority is updated, the notification flow for that alert will restart if the new priority is higher than the previous priority level.
  • What are alert priorities?By default, the top 5 alert priorities will be assigned to the top 5 incident priorities
  • What are alert priorities?Alerts will automatically be created when someone is assigned, added as a responder or owns a service on the incident.

  • Change project customer permissionsWhen channel access is restricted, users can still raise request by chat such as Slack and Microsoft teams.

動手做

實作 Lab：逛 Features 頁，替 queue 加 board 與 calendar

約 20 分鐘Project admin；Jira admin（非 ITSM project 開 Alerts、On-call；alert priority 對應）；Premium（Problems、Changes、PIR）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：找出 Features 頁的開關與 Feature lab，在 queue 上加 board、calendar view，並看 work categories 與 alert priority 的對應在哪裡。

這個 Lab 對應的考點

Problem、Change、post-incident review 要 Premium／Enterprise；Alerts、On-call 所有 project 類型都能開，Services 只有 ITSM；Feature lab 的功能可能不會正式推出；alert priority 對應 incident priority。

步驟

  1. 你應該看到：一列一個開關；最下方有 Feature lab 區，列出可以試用的新功能。
  2. 你應該看到：通常會看到依 work category 分區的 queue：Service requests、Incidents、Problems、Changes、Post-incident reviews（Premium 才有後三個）。
  3. 你應該看到：每個 request type 屬於一個 work category；Problem、Change 的 request type 在各自的分類下。
  4. 你應該看到：Queue 上方多了 Board 分頁；預設三欄，對應 To do、In progress、Done。
  5. 你應該看到：可以調整欄位與 status 的對應，也能改卡片顏色、swimlane。
  6. 你應該看到：只填 due date 的出現在當天；只填 start date 的不會出現。日期欄位要先放進 request type 才能填。
  7. 你應該看到：每個 incident priority 對應一個 alert priority（P1–P5）；預設前 5 個 incident priority 對到 P1–P5。這是全域設定，改了會影響所有 project。

試試看：改一個設定，觀察差異

T1（想像，不實際做）站台從 Premium 降到 Standard。看結果
Problems、Changes、PIR 的資料不會遺失；它們的 request type 變成 Unassigned，work item 移到 All queues。
T2在 Feature lab 打開一個試用功能，看側欄或 request 有什麼變化，再關掉。看結果
功能出現或消失。Feature lab 的功能可能改變、偶爾會壞、也可能不正式推出。
T3（想像，不實際做）在一個非 ITSM 範本的 service project 打開 Features。看結果
Alerts、On-call 可以開（要 Jira admin）；Services 沒有，它只給 ITSM project。

  • 移除練習加的 Board、Calendar view（滑到分頁上 → More actions → Remove）。
  • Feature lab 的試用功能關掉；清掉練習填的日期。
