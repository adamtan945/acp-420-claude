Features 開關

3 分鐘速覽

Features 頁：要用什麼功能自己開

  1. 位置Space settings → Features：用開關啟用或停用功能。
  2. Board 與 calendar考綱寫在 Feature tab；現行 Cloud 改在 queue 上用 Add to navigation 加 board、calendar view（Jira admin 或 space admin）。
  3. Work categoriesService requests、Incidents、Problems、Changes、Post-incident reviews；決定側欄分區與 request type 分類。
  4. 方案限制Problem、Change、major incident、post-incident review 只有 Premium／Enterprise（2024/10/16 起）。
  5. Alerts、On-call 任何 project 都能開；Services 只有 ITSM project在非 ITSM project 開這些要 Jira admin。
  6. Feature labFeatures 頁最下方，試用尚未正式發布的功能。
Work categories

什麼時候開哪一種

Work category處理什麼什麼時候開
Service requests例行請求：申請權限、借設備、問問題幾乎都要；IT、HR、Facilities 都適用
Incidents服務中斷或品質下降，要盡快恢復有營運服務、需要 on-call 處理事故
Problems找出一再發生的 incident 的根本原因同類 incident 重複發生，要做根本原因分析（Premium 以上）
Changes要審核、排程、評估風險的變更部署、設定變更要 CAB 核准、需要 change calendar（Premium 以上）
Post-incident reviews事故後檢討重大事故後要留紀錄與改善項目（Premium 以上）
降級時不掉資料

官方：從 Premium 降到 Standard 時資料不會遺失；Changes、Problems、PIR 的 request type 變成 Unassigned，work item 移到 All queues。

  • 一般請求→Service requests；中斷→Incidents；根因→Problems；變更→Changes；事後→PIR。

Incident 協作

Alert 與 incident 的 priority、chat 工具

  • Alert priority：P1 Critical、P2 High、P3 Moderate、P4 Low、P5 Informational。Priority 提高時通知流程會重新開始。
  • 對應 incident priority：Space settings → Operations → Incident management → Assign alert priorities。預設前 5 個 incident priority 對應 P1–P5；新增的 incident priority 對應最低的 P5。這個對應由 Jira admin 在全域設定，會影響所有使用 incident management 的 project。
  • Responder alerts：有人被指派、被加成 responder、或是受影響服務的 owner 時會自動建 alert；建議把 Responders 欄位加進 incident 的 request type。
  • Chat 工具（incident 協作）：從 incident 建立 Slack／Teams 頻道、自動加入 responder、在頻道裡更新與摘要；屬於 Premium 的進階 incident 功能。
  • Chat 提單（另一件事）：在 Space settings → Channels & self service → Chat 設定，讓 customer 從 Slack／Teams 提單；Restricted channel access 也擋不住 chat 提單。
本段必考
  • Alert P1–P5；可以跟 incident priority 不同。
  • Priority 變高，通知流程重來。
