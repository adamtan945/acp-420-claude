3 分鐘速覽

會用、不會設：Assets 給工單加上「哪台、哪個、誰的」

  1. 考綱明說只考使用Utilize, but not configure：認得 schema、object type、object、attribute，會在 request 裡引用它們。
  2. 四層Object schema → object type → object → attributes。
  3. Object schema一組相關資料（例如 IT 資產）；有自己的權限。
  4. Object type同類 object 的群組（Laptop、Server）；可有 parent／child、繼承 attributes、可設 abstract。
  5. Assets object 欄位Jira 的 custom field，讓 request 連到 object；雙向連結，object 頁看得到相關 work item。
  6. 在哪用Request type 表單、forms、queue 欄位、JQL、automation（AQL）。

四層模型

Schema、type、object、attribute

名詞是什麼例子

在 request 引用

Assets object 欄位

  • Assets object 是一種 Jira custom field；建立與編輯要 Jira 授權（通常由 Jira admin 建、加到 screen 與 request type）。
  • 加進 request type 的表單後，customer 提單時就能選「哪一台電腦」「哪個系統」。
  • 連結是雙向的：work item 上看得到 object，object 頁看得到所有相關的 work item（追根因、評估變更影響）。
  • 欄位設定有三種過濾：Object schema（必填）、Filter scope（AQL）依 Assets 資料過濾、Filter work scope（AQL）依目前 work item 的其他欄位過濾（可做連動選單，例如先選 Manufacturer 再選 Model）。
  • Filter work scope 可用 placeholder，例如 objectType = "Laptop" AND Owner LIKE ${reporter.label}：只列出提單人自己的筆電；可勾 Display a default object in the customer portal。
  • 也可以放在 forms、當 queue 的欄位、用在 automation（Lookup objects、Edit object）。
  • 限制：Assets object 欄位不能拿來在 JQL 排序（ORDER BY）。

動手做

實作 Lab：從 Assets schema 一路點到 request

約 30 分鐘Jira admin（建 Assets object 欄位，要有 Jira 授權）；project admin（request type）；Standard 以上（Assets 含在付費方案）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 Assets 認出 schema、object type、object、attribute 四層，再透過 Assets object 欄位把一台筆電掛到 request 上，從兩端看這條雙向連結。

這個 Lab 對應的考點

Object schema → object type → object → attribute；Assets object 欄位建立雙向連結；Filter scope 依 Assets 資料、不能用 placeholder；Filter work scope 依目前 work item、可以用 placeholder；不能用 Assets object 欄位在 JQL 排序。

準備

  • 考試只考「會用」，以下是準備資料，不是考點：在 Assets 建一個 object schema Lab IT，建 object type Laptop，加一個 User 類型的 attribute Owner；建兩個 object：MacBook-Leo（Owner＝Leo）、MacBook-Ana（Owner＝Ana）。

步驟

  1. 你應該看到：左邊是 object type 的樹狀清單（Laptop）；schema 有自己的設定與權限。
  2. 你應該看到：除了你加的 Owner，還有每個 object 都有的預設 attributes：Name、Key、Created、Updated（部分站台另有 Display name）。
  3. 你應該看到：Key 是 schema key＋數字（例如 LIT-1），不能改；Owner 顯示 Leo。
  4. 你應該看到：AQL 語法正確時旁邊出現打勾；Object schema 是必填，另外兩個是選填。
  5. 你應該看到：表單上多了 Your laptop 欄位。
  6. 你應該看到：通常只列出 MacBook-Leo，沒有 MacBook-Ana：Filter work scope 用提單人過濾。選它並送出。
  7. 你應該看到：Object 頁看得到這張 request：連結是雙向的。
  8. 你應該看到：Queue 多一欄，直接看到每張 request 掛的是哪台筆電。

試試看：改一個設定，觀察差異

T1把 ${reporter.label} 那段改放到 Filter scope。看結果
Filter scope 不能用 placeholder：通常會驗證失敗或過濾不出東西。Placeholder 只能用在 Filter work scope。做完改回。
T2在 work item 搜尋寫 project = HELP ORDER BY "Your laptop"。看結果
不能用 Assets object 欄位排序搜尋結果。
T3（選做）建一個 object type Hardware 設成 abstract，把 Laptop 放到它底下，再試著在 Hardware 直接建 object。看結果
做不到：abstract 型別不能放 object，只把 attributes 傳給 child。
心像錨點：閉上眼睛想一次這個畫面

Assets 左邊的樹：Lab IT → Laptop；右邊 MacBook-Leo 的頁面下方掛著那張 request。Request 看 object、object 看 request。庫、類、件、性。

收尾

  • 從 request type 的表單移除 Your laptop；queue 移除這一欄。
  • Lab IT schema 與 Your laptop 欄位可以留著，之後的 Lab 可能用得到。
