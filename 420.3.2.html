3 分鐘速覽

Service：讓 incident 與 change 知道「影響到誰」

  1. Service 是全站的跨所有 service project 使用；考試版在 Features 開 Services（只有 ITSM project）。
  2. 每個 service 有Tier、owner team、change approvers、responders、stakeholders、references（依賴其他 service）、type（只是分類）。
  3. Tier 1–4Tier 1 最關鍵；可當 automation 與 alert 的條件。
  4. Affected services 欄位把 service 加到 incident、change；從 graph 看上下游。
  5. 加了 service 不會自動通知或改 priority要通知 owner team 就加 responder；priority 跟 tier 走要寫 automation。
  6. 現行底層是 AssetsSoftware Registry 與 Business Portfolio 兩個 schema；權限看 Assets schema。

  • What are services?A tier, which defines how critical the service is to business operations.

Service 的組成

一個 service 設定什麼

屬性用途
Tier多關鍵：Tier 1 失效重大影響 customer 或營收；Tier 4 幾乎無感
Owner team負責的團隊；它的 on-call schedule 會顯示在 service 頁
Change approvers這個 service 的 change 要誰核准
RespondersService 出事時被通知的人或 team
Stakeholders不直接處理、但要知道 incident 進度的人
References／relationships依賴哪些 service（Depends on），用來推算影響範圍；每個 service 最多 100 個
Type分類標籤，沒有技術影響
本段必考
  • Tier＝關鍵程度；references＝依賴。
  • Type 只是標籤。

日常使用

在 incident、change、request type 用 service

  1. 啟用考試版：Space settings → Features 開 Services（只有 ITSM project，非 ITSM 不提供）。現行：側欄 Operations → Services。
  2. 建立與設定建 service、設 tier、owner team、change approvers、responders、stakeholders、references。
  3. 加到 request type在 incident、change 的 request type 加 Affected services（或 Service）欄位，讓提單人或 agent 選受影響的服務。
  4. 在 work item 加／移除打開 incident 或 change → Affected services 欄位加入或按 Remove 移除；沒有 Jira 授權的人看不到這個欄位。
  5. 看影響Incident 頁顯示上游（它依賴的）與下游（依賴它的）service。
  6. 自動化Automation 的 Affected services condition：例如 Tier 1 service 受影響時寄信給主管、或把 priority 設成 Highest。
不會自動發生的事

官方：把 service 加到 incident 不會自動通知 owner team、也不會依 tier 設 priority。要通知就把 owner team 加成 responder；要依 tier 設 priority 就寫 automation rule。

權限

誰能改 service

  • Service 是 Assets 的 object：權限由 Assets schema（global、schema、object type 三層）決定，不是 JSM project role。
  • 編輯 service、管理 references、換 owner team、刪除、改 attribute 都要該 schema 的編輯權限。
  • 兩個預建 schema：Software Registry（技術服務：Applications、Capabilities、Software Services、Deployed Services）與 Business Portfolio（Business Services）。
本段必考
  • 看得到但不能改 → 查 Assets schema 權限。

  • Configure Services: settings, permissions, and referencesActions that require edit permission on the relevant schema or service object type include:
  • What are services?Software Registry – Use this schema to store your technical services, such as software services, microservices, applications, and other building blocks of your technical architecture.
  • What are services?Business Portfolio – Use this schema to store your customer-facing services, such as UI pages, APIs, customer portals, and other services your customers directly interact with.

動手做

實作 Lab：建三個 service，看 incident 的影響範圍

約 25 分鐘Assets 中 service schema 的編輯權限（你是 admin 即可）；Standard 以上；ITSM project

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：建三個有依賴關係的 service，把其中一個加到 incident 的 Affected services，看上下游；再確認哪些事情「不會自動發生」，用 automation 補上。

這個 Lab 對應的考點

Service 全站共用、底層是 Assets；tier、owner team、references 要自己設；把 service 加到 incident 不會自動通知 owner team、也不會依 tier 設 priority；tier 可以當 automation 的條件。

準備

  • Ops 已啟用 operations（環境頁）。

步驟

  1. 你應該看到：Services 清單（可能是空的）。若看不到 Services：新版 Services 可能尚未推到你的站台，或缺 Assets schema 權限。
  2. 你應該看到：每個 service 必填 Name、Tier、Service object type 三項。
  3. 你應該看到：Service 詳細資料裡出現 Ops 的 on-call schedule。
  4. 你應該看到：Reference 類型預設是 Depends on。
  5. 你應該看到：圖上 Website 與 Mobile app 都指向 Payment platform：它出事，兩個都受影響。
  6. 你應該看到：Incident 上看得到上下游的 service；priority 仍是 Medium，Ops 也沒有收到任何通知。
  7. 你應該看到：Service 可以隨時加、移除。
  8. 你應該看到：Customer 看不到 Affected services 欄位（沒有 Jira 授權的人看不到）。

試試看：改一個設定，觀察差異

T1Space settings›Automation 建一條 rule：Work item created → condition Affected services（tier 是 Tier 1）→ action 把 priority 設成 Highest。建一張新 incident，Affected services 選 Payment platform。看結果
新 incident 的 priority 變成 Highest。依 tier 設 priority 要靠 automation，不會自己發生。做完停用這條 rule。
T2在步驟 6 的 incident 的 Responders 加入 Ops。看結果
Ops 收到 responder alert。要通知 owner team，就要把它加成 responder。
T3（想像，不實際做）沒有 Assets schema 編輯權限的人打開 Payment platform。看結果
看得到但不能改：service 的權限看 Assets schema，不看 JSM project role。
心像錨點：閉上眼睛想一次這個畫面

Payment platform 的 graph：上面一個 Tier 1 方塊，下面兩條線接著 Website 和 Mobile app。旁邊的 incident priority 一動也不動：加了 service 不會自己通知、不會自己改 priority。

收尾

  • 停用（或刪除）練習用 automation rule。
  • 三個 service 可以留著，之後 change、incident 的 Lab 用得到。
  • 關閉練習用 incident。
