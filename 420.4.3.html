3 分鐘速覽

一封 email 變成一張 request

  1. 預設 Atlassian email每個 service project 有一個 xxx@公司.atlassian.net；最多連 10 個 email address。
  2. 自訂 emailCreate Atlassian email（新前綴）或 Add external email（Google、Microsoft 用 OAuth；Other 用 IMAP／POP）。
  3. 每個 email 對一個 request typeRequest type 只能 Summary、Description 是必填；多加必填欄位 email 就建不了 request。
  4. Allowlist只填 domain、完全比對；DMARC 啟用時（預設），驗證失敗的信仍會被過濾。
  5. BlocklistDomain 或單一 email address；同時在兩邊時 blocklist 優先。
  6. 關閉Channels & self service → Email → More → Disable all email requests。

Email 帳號

連接 email 與選 request type

  1. 位置Space settings → Channels & self service → Email。
  2. 新的 Atlassian emailCreate Atlassian email → 輸入前綴（support → support@公司.atlassian.net）→ 選 request type。
  3. 外部 emailAdd external email（Jira admin 或 project admin）：Google、Microsoft 走 OAuth（可能要對方 admin 同意）；Other 填 IMAP／POP 資訊。外部帳號改密碼後連線會中斷，要重新連。
  4. 選 request type每個 email address 指定一個 request type；Edit 可改。
  5. 補抓舊信OAuth／IMAP 帳號可設 Start processing emails from（最多連線前 7 天）。
Email 用的 request type

官方：給 email 用的 request type 必須顯示 Summary 與 Description，其他可見欄位都要是選填；Description 不能移除。多加必填欄位，該 email 寄來的信就不會建立 request。

其他設定

Email 管道的周邊行為

  • 關閉 email：Email → More actions → Disable all email requests → Turn off；信不再變成 request。要刪除 email 用的 request type，也得先這樣關掉。
  • 誰能用 email 提單：受 customer permissions 影響（420.1.2）；site 不允許建帳號時，陌生寄件者的信不會被處理；Restricted channel access 時只有被邀請的 customer。
  • CC 的人：customer 寄信時 CC 的人可以成為 request participant（依設定）。
  • Email logs：查看 incoming email processing 與 connectivity logs，排查信為什麼沒變 request。
本段必考
  • Email 沒變 request：查 request type 必填欄位、blocklist、customer permissions、logs。

動手做

實作 Lab：寄一封信，看它變成 request 或被擋下

約 30 分鐘HELP 的 project admin（Add external email 要 Jira admin 或 project admin）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：用 HELP 內建的 Atlassian email 與新建的 Atlassian email 收單，體驗 request type 必填欄位、blocklist、allowlist 與關閉 email 的效果。

這個 Lab 對應的考點

每個 project 最多 10 個 email、每個對一個 request type；email 用的 request type 只能有 Summary、Description 必填；allowlist 只收 domain，blocklist 收 domain 或 email；兩邊都有時 blocklist 優先。

準備

  • 前提：要有一個能寄信的信箱扮演 Cara。Lab 不需要外部 email 帳號連進 JSM，用的是 HELP 內建的 Atlassian email（xxx@你的站台.atlassian.net）。Cara 若是 email 別名，請先讓這個別名可以當寄件人（例如在信箱設定加入「以這個地址寄信」）；做不到就用另一個你自己的私人信箱，並先把它邀請成 HELP 的 customer。
  • HELP 的 Space settings›Access›Customer permissions 維持環境頁的起點：Channel access 為 Open（Cara 已是 HELP 的 customer，可以用 email 提單）。
  • 沿用 420.4.1 的 Lab 借用投影機（有一個必填的 Due date）。

步驟

  1. 你應該看到：至少有一個內建的 Atlassian email，旁邊寫著它的 request type、Incoming logs 與最後收信時間。
  2. 你應該看到：幾分鐘後 HELP 仍沒有新 request：這個 request type 有 Summary、Description 以外的必填欄位（Due date），email 建不了 request。
  3. 你應該看到：HELP 多了一張 Get IT help 的 request，reporter 是 Cara；Cara 在 portal 的 Requests 也看得到。
  4. 你應該看到：沒有新 request：blocklist 裡的 email 永遠被過濾。
  5. 你應該看到：Allowlist 只接受 domain，不支援單一 email address。即使 domain 在 allowlist，Cara 仍在 blocklist，通常仍不會建立 request（官方 team-managed 文件寫明 blocklist 優先；company-managed 文件未提）。
  6. 你應該看到：信不再變成 request。這也是刪除 email 用的 request type 之前要做的事。

試試看：改一個設定，觀察差異

T1（需要你自己的 Google 或 Microsoft 信箱；沒有就只看不做）Add external email → Continue with Google（或 Microsoft）→ 完成授權。看結果
清單多一個外部 email，授權後可以改它的 request type。外部帳號改密碼後連線會中斷，要重新連。做完 Remove。
T2試著再建第 11 個 email address（只看提示，不必真的建到 10 個）。看結果
一個 service project 最多連 10 個 email address。
T3在 Get IT help 的 request form 移除 Description。看結果
通常做不到：email 管道靠 Description 處理信件內容，給 email 用的 request type 不能移除它。
心像錨點：閉上眼睛想一次這個畫面

Email 頁的連接清單：每一列一個信箱、一個 request type、一個 Incoming logs 連結。十個信箱、一信一型；白名單只認 domain、黑名單說了算。

收尾

  • 重新開啟 email requests（在同一個 More 選單找開啟的選項；名稱以畫面為準）。
  • 刪除 lab-help 這個 Atlassian email；確認 blocklist、allowlist 已清空。
