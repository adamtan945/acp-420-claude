3 分鐘速覽

知識庫＝連到 service project 的 Confluence 內容

  1. 連結Space settings → Channels & self service → Knowledge base → Set up knowledge base／Add knowledge：可連 space、folder 或 page（含所有子頁）。
  2. 取消連結Unlink：只從 service project 移除，Confluence 裡的 space 還在。
  3. Who can viewAnyone（不登入、會被搜尋引擎找到）／All logged-in users／Only Confluence users。
  4. Who can editService space users（agent、admin 可在 JSM 寫文章）／Only Confluence users。
  5. Site 設定先決定選項Jira admin 在 Products → JSM → Knowledge base permissions 開 All logged-in users、Anyone；沒開，project admin 就選不到。
  6. Internal vs externalExternal 給 customer（portal、help center、virtual agent）；internal 只給 agent。
資料來源（5）有疑慮時點開看官方原文
  • Link a Confluence source to your knowledge baseYou can link a Confluence space, folder, or page to your Jira Service Management knowledge base.
  • Unlink knowledge base spaces from your service projectUnlinking spaces only removes them from your service space. These spaces will still be available in Confluence.
  • Manage who can view and edit your knowledge base articlesChoose this option if you want to make sure that articles in this space are open to all in your help center, even those who haven’t logged in.
  • Manage knowledge base permissionsAnyone - Turn on this option if you want project admins to have the flexibility of making articles in a space publicly accessible.
  • The difference between internal and external knowledge basesArticles in an external knowledge base can be accessed via customer-facing channels like the help center, portal, and virtual service agent.
連結

連結與取消連結 Confluence

  1. 第一次Knowledge base → Set up knowledge base → 選 space、folder 或 page → Link。
  2. 加更多Add knowledge → 選內容 → Link。已經連了整個 space，就不用再加其中的 page；只想要某個 folder，要先 unlink 整個 space。
  3. 出現在哪Knowledge base 的 Articles 清單、portal 與 help center 搜尋結果、virtual agent 的推薦答案。
  4. 取消Knowledge base → 選 space → Unlink → Confirm；可多選一次 unlink。Space 仍在 Confluence。
本段必考
  • 連 page 或 folder 會帶入所有子頁。
  • Unlink 不會刪 Confluence 內容。
資料來源（5）有疑慮時點開看官方原文
  • Link a Confluence source to your knowledge baseWhen linking content, all children (descendants) of the linked content will be available, as long as permissions are set correctly.
  • Link a Confluence source to your knowledge baseIf you only want a specific folder or page to be added from a space that is already available, you need to unlink that space first.
  • Link a Confluence source to your knowledge baseArticles from Confluence then appear in your help center, knowledge base search, and the Virtual Service Agent.
  • Unlink knowledge base spaces from your service projectYou can also select multiple spaces and unlink them from your service space at once.

權限

誰能看、誰能寫

Who can view誰看得到前提
Anyone網路上任何人，不用登入；會被 Google 搜到Site 開 Anyone；Confluence 付費方案（Standard 以上）；portal 要公開（anyone can send a request）
All logged-in users登入 service project 或 help center 的人（含 customer）Site 開 All logged-in users
Only Confluence users有 Confluence 授權、能存取該 space 的人永遠可選
Who can edit誰能寫
Service space usersAgent 與 admin 能在 JSM 建立、編輯文章
Only Confluence users只有有 Confluence 授權的人；細部權限在 Confluence 管
改不了 Who can view？

Confluence 的全域權限（例如 anonymous access 的 View）與 KB 設定衝突時會鎖住選項；到 Confluence space settings 開或關 Anonymous access 的 View。

動手做

實作 Lab：把 Help KB 接上 HELP，再調整誰能看

約 30 分鐘HELP 的 project admin；site 層 Knowledge base permissions 要 Jira site admin（同時是 Confluence admin 才能改，否則唯讀）；Anyone 要 Confluence Standard 以上的付費方案

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：連結 Confluence space Help KB，從 site 層與 project 層調整 Who can view／Who can edit，用 customer 與未登入路人兩個視角驗證，最後 unlink。

這個 Lab 對應的考點

Site 層決定 project admin 有哪些 Who can view 選項；Anyone＝全網公開，要 site 開、Confluence 付費、portal 公開；Confluence 的頁面限制一定被尊重；unlink 不會刪 Confluence 內容。

準備

  • Confluence space Help KB 有 3 篇文章，其中一篇「內部排錯步驟」在 Confluence 加了頁面限制（只有你能看）。
  • 步驟 6 要讓 portal 公開（官方前提：任何人都能透過 portal 送 request）：暫時把 ⚙ Settings›Products›Jira Service Management›Customer access 改成允許不登入就送 request，HELP 的 Channel access 維持 Open。不想改站台設定，步驟 6 就只看不做。

步驟

  1. 你應該看到：這兩個開關決定 project admin 在 KB 設定裡能選哪些 Who can view。
  2. 你應該看到：清單出現 Help KB，旁邊有 Who can view 與 Who can edit 兩個下拉選單（在 External knowledge base 分頁）。
  3. 你應該看到：只有 All logged-in users 與 Only Confluence users，沒有 Anyone：site 層沒開。
  4. 你應該看到：Cara 搜得到一般文章；未登入路人搜不到。
  5. 你應該看到：找不到：Confluence 的頁面限制一定被尊重，KB 設定蓋不過它。
  6. 你應該看到：未登入也看得到一般文章（也可能被搜尋引擎收錄）。如果選單仍沒有 Anyone：檢查 Confluence 方案、portal 是否公開、Confluence 的 anonymous access 設定。
  7. 你應該看到：Leo 不用進 Confluence 就能在 JSM 建立文章，文章出現在 Help KB。
  8. 你應該看到：HELP 的 KB 清單與 portal 搜尋不再有 Help KB；Confluence 裡的 Help KB 與文章都還在。

試試看：改一個設定，觀察差異

T1在 Help KB 仍整個連結的情況下，用 Add knowledge 再加其中一個 page。看結果
不必加：整個 space 已經連了，內容都可用。只想要某個 folder 或 page，要先 unlink 整個 space，再單獨連。
T2切到 Internal 分頁，把另一個 Confluence space 連成 internal knowledge base，用 Cara 搜尋它的文章。看結果
Cara 搜不到：internal KB 只給 agent，而且不能在 KB 設定管權限、不能從 JSM 建文章。做完 unlink。
T3把 site 層的 All logged-in users 與 Anyone 都關掉，再看 Help KB 的 Who can view。看結果
只剩 Only Confluence users：沒有 Confluence 授權的 Cara 就看不到文章了。
心像錨點：閉上眼睛想一次這個畫面

Knowledge base 設定頁：Help KB 一列，右邊兩個下拉選單 Who can view、Who can edit，Who can view 的選項多寡由 site 層兩個開關決定。站給選項、專案選、Confluence 守門。

收尾

  • 重新把 Help KB 連到 HELP（420.6.2 與 420.5.2 會用），Who can view 設 All logged-in users，Who can edit 設 Service space users。
  • Site 層把 Anyone 關回去；Customer access 改回環境頁的起點（Allow customers to create accounts、不勾 without logging in），HELP 的 Channel access 維持 Open。
