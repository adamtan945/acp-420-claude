3 分鐘速覽

什麼時候該用 automation

  1. 重複性工作自動更新欄位、指派、轉 status、寄通知——人每天手動做同一件事，就是 automation 的候選。
  2. SLA 快違約SLA threshold breached trigger：違約前 X 分鐘通知 agent、提高 priority、留言給 customer。
  3. 取代內建通知內建 customer／internal notification 不夠細時，用 automation 寄更貼切的訊息（特定 request type、特定時機、特定收件人）。
  4. 連動 AssetsWork item 到某 status 時，Edit object／Assets 動作把設備的 Status 屬性改成 In repair。
  5. 不是什麼都要 automation一次性的大量修改用 bulk change；每次 transition 必做且要保證一致的用 post function。
  6. Auto-resolve／auto-closeWaiting for customer 超過 N 天沒回 → 自動解決並通知。

避免重複通知

用 automation 取代某個內建通知時，記得把對應的 customer notification 規則關掉（Enable off），否則 customer 會收到兩封。

動手做

實作 Lab：只對一種 request 寄取件說明

約 25 分鐘HELP 的 project admin（單一 project 的 rule）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：用一條帶 condition 的 rule 取代內建通知做不到的「只針對某個 request type」的訊息，再設一條 SLA 快違約的提醒，最後判斷幾個需求該不該用 automation。

這個 Lab 對應的考點

要「對的人、對的時機、對的內容」→ automation；SLA threshold breached 可設違約前或違約後；用 automation 取代內建通知時要關掉對應的 customer notification；一次性用 bulk change，每次 transition 必做用 post function。

準備

  • 沿用 420.4.1 的 Lab 借用投影機，Cara 各有一張 Lab 借用投影機與 Get IT help 的 request。

步驟

  1. 你應該看到：Rule 編輯器出現 trigger；一條 rule 只能有一個 trigger。
  2. 你應該看到：不寫 JQL 就能限定 request type，這是內建 customer notification 做不到的。
  3. 你應該看到：Rule 清單出現這條 rule，狀態是啟用。
  4. 你應該看到：只有 Lab 借用投影機那張出現這則留言，Cara 也會收到公開留言的通知；Get IT help 那張沒有。
  5. 你應該看到：兩筆執行紀錄：一筆有做事（Success），一筆被 condition 擋下（No actions performed）。
  6. 你應該看到：Trigger 設定裡可以選要監看的 SLA，以及違約前或違約後多久觸發。要等 SLA 計時到那個點才會跑，通常要過一段時間再看 audit log。
  7. 你應該看到：Bulk change／workflow post function／automation（Scheduled＋JQL）／automation（Assets 相關 action）。

試試看：改一個設定，觀察差異

T1「Lab 取件說明」啟用時，同時看內建 customer notification 的 Public comment added 規則。看結果
Cara 收到的是內建規則寄的公開留言通知。如果你改用 automation 直接寄 email 給 Cara，就要把重疊的內建規則關掉，否則她會收到兩封。
T2（想像，不實際做）HELP 有 Assets schema，work item 上有一個 Assets 欄位指向某台筆電；rule 在 work item 轉到 Repair 時用 Edit Assets field attributes 把 Status 屬性改成 In repair。看結果
這是考綱的典型情境；值的型別要和屬性一致，否則 rule 會出錯。環境頁留下的 Assets schema Lab IT 可以拿來實做，但 HELP 要先有指向它的 Assets 欄位，本 Lab 不展開。
T3把「Lab SLA 提醒」的時間改成「違約後」。看結果
變成違約後才升級與提醒：同一個 trigger 前後都能設。
心像錨點：閉上眼睛想一次這個畫面

Rule 編輯器的三個方塊：Work item transitioned → Request type equals Lab 借用投影機 → Comment on work item。重複、快違約、更精準、連資產，才用 automation。

收尾

  • 停用（或刪除）「Lab 取件說明」與「Lab SLA 提醒」。
  • 把被改成 Highest 的 request priority 改回。
