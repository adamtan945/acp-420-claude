考綱列出的 trigger、condition、action

類型元件用途與限制
TriggerApproval required／Approval completed需要核准時通知 approver；核准或拒絕後轉 status、通知 customer
TriggerObject created／updated／deletedAssets object 變動時；只能用在 global rule
TriggerSLA threshold breached選 SLA 與「違約前／後多久」；提醒、升級 priority
TriggerForm submitted表單送出時（form 相關步驟只能在 project rule）
ConditionAffected services依 service tier、名稱、依賴服務判斷（ITSM project）
ConditionForms attached檢查是否附了某些表單、表單狀態
ConditionAQLAssets object 或 issue 的 Assets 欄位是否符合 AQL
ActionApprove/decline request自動核准低金額、標準變更
ActionAdd service project customer把 email 加成 customer（可放進 organization）；連續呼叫可能要加 Delay
ActionCreate incident建立指定 request type 的 incident；可避免重複建立
ActionCreate work item with a request type用 request type 建單；隱藏欄位不支援
ActionEdit request type改 request type；新 request type 要對應同一個 issue type，否則錯誤
ActionLookup objects／Create object／Edit objectAQL 查最多 100 個 object（{{lookupObjects}}）；建立 object；Edit object 只在 global rule 且 object 是焦點時
ActionAttach forms／Copy forms附表單、從其他 work item 複製表單；只能 project rule

  • Form 元件只能 project rule。
  • Edit request type 要同一個 issue type。

管理

啟用、停用、標籤

  • Rule 清單的開關可以 Enable／Disable；停用的 rule 不會觸發，但設定保留。
  • Labels：Automation 頁 Add label（名稱、顏色）→ 把 rule 拖到 label 上；可依 label 篩選。Global 與 project rule 共用 label。
  • Rule details：Name、Description、Owner（錯誤時收 email）、Notify on error、Who can edit（Private／Specific admins／All admins）。
  • Rule settings：Allow rule trigger（能否被其他 rule 觸發）、Scope、Actor。
本段必考
  • Labels 只是分類，不影響執行。

動手做

實作 Lab：做一條 auto-resolve，用 smart values 除錯

約 30 分鐘HELP 的 project admin；用 Rovo 產生 rule 要站台已啟用 Rovo（Atlassian Intelligence）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：用 Scheduled trigger＋JQL 做自動解決，用 Log action 印出 smart values，替 rule 加 label、停用再啟用，最後請 Rovo 產生一條 rule。

這個 Lab 對應的考點

Auto-resolve／auto-close 常用 Scheduled＋JQL；smart values 處理文字、清單、日期、數字與變數；labels 只是分類、global 與 project rule 共用；Rovo 產生 rule 至少要描述 trigger 與 action。

準備

  • Cara 有一張 request 在 Waiting for customer，並加上兩個 label（例如 vpn、urgent）。

步驟

  1. 你應該看到：Scheduled trigger 帶 JQL 時，後面的 action 會對查到的每張 work item 執行。正式用時把 -10m 改成 -3d。
  2. 你應該看到：Rule 依序有 trigger、兩個 action。
  3. 你應該看到：Rule 存好並啟用。
  4. 你應該看到：Request 轉成已解決，History 顯示是 Automation for Jira 做的；audit log 展開後看得到 Log action 印出的 labels 字串、天數、3 個工作天後的日期與大寫 summary。
  5. 你應該看到：清單只剩貼了 lab 的 rule。Label 只是分類，不影響執行。
  6. 你應該看到：停用期間它不會被處理，rule 的設定都還在。
  7. 你應該看到：Rovo 產生 trigger＋action 的草稿；檢查並補齊細節後才決定要不要 Enable flow（本 Lab 不必啟用）。

試試看：改一個設定，觀察差異

T1在 HELP 的 rule 加 action Edit request type，改成一個 work type 不同的 request type，讓它跑一次。看結果
Audit log 出錯：新的 request type 要對應同一個 work type。
T2在 HELP 的 rule 找 trigger Object trigger（Assets object 建立、更新、刪除）。看結果
通常找不到或不能選：object 相關 trigger 只能用在 global rule。反過來，form 相關的步驟只能用在 project rule。
T3把 Log action 改成 {{#=}}{{issue.created.diff(now).days}} * 24{{/}}。看結果
Audit log 印出換算成小時的數字：數學運算要包在 {{#=}}…{{/}}。
心像錨點：閉上眼睛想一次這個畫面

Audit log 展開的一行：Log action 印著 labels=vpn, urgent／due=三個工作天後的日期。Scheduled＋JQL 做 auto-close，Log action 是除錯神器。

收尾

  • 停用「Lab auto-resolve」（或把 JQL 改回 -3d 再保留），刪除 Rovo 預覽產生的草稿。
  • lab label 可保留給 420.8.3 用。
