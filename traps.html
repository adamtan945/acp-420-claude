420.1.1 使用者、角色與權限類型5 條

Collaborator 只要權限給夠，就能回覆 customer。
Collaborator 只能 internal comment；官方明說給它更多權限也不會被支援。要公開回覆就要 JSM agent 授權。
官方來源
把 customer 的權限授權給 Service Desk Customers role 最標準。
要給 Service Desk Customer - Portal Access security type。
Role 只是用來辨識誰是 customer。
官方來源
Request participant 一定看得到被分享的 request。
Participant 仍受 issue security 限制；security level 只開給 reporter 時，participant 看不到。
官方來源
Customer organization 就是 admin.atlassian.com 的 organization。
兩者無關：customer organization 是 JSM 裡 customer 的群組；Atlassian organization 是集中管理使用者與產品存取的單位。
官方來源
Customer 會佔一個 JSM 授權。
Customer 免費；只有 agent 佔 JSM 授權。
官方來源

420.1.2 Customers 與 organizations6 條

Project admin 把 Channel access 設成 Open，就等於任何人都能匿名提單。
Open 只是沿用 site 的 customer access；site admin 沒勾「without logging in」就還是要登入，沒允許建帳號就只有既有帳號能提單。
官方來源
Restricted 之下，所有管道都只剩被邀請的人能提單。
Chat（Slack、Teams）不受 channel access 限制；提單的人會被自動邀請進 project。
官方來源
在 project A 新增的 customer detail field 只出現在 project A。
Detail fields 是全站的，所有 customer 都會出現。
官方來源
Detail field 建錯類型，直接改類型就好。
建好後只能改 label；類型不能改，要刪掉重建（資料會一起刪除）。
官方來源
替 organization 加 email domain 後，既有 customer 會自動被歸進去。
只影響之後新加入的 customer。
官方來源
選 Don't allow customers to create accounts 後，陌生人寄 email 仍會建立 request。
未知寄件者的 email request 不會被處理。
官方來源

420.1.3 管理團隊成員5 條

Project admin 可以從 Invite team 加任何人當 agent。
只能加已有 JSM 授權的人；新 agent 要 org admin。
官方來源
Default assignee 可以設成任何 agent。
只能 Unassigned 或 project lead。
官方來源
Project admin 能把人加進 group 來給權限。
Group 成員只有 Administer Jira 能改；project admin 改的是 role 成員。
官方來源
給非 agent 的 Jira 使用者 Add comments 權限，他們就能回覆 customer。
只能 internal comment，不能分享給 customer。
官方來源
移除 agent 授權只影響一個 service project。
授權是全站的：所有 service project 都不能再當 agent。
官方來源

420.2.1 Queues5 條

一個 queue 只能放進一個 priority group。
可以屬於多個 group。
官方來源
所有 queue 都會即時更新數字。
只有 Starred 與 priority groups 會定期刷新；View all queues 不刷新。
官方來源
remaining("2h") 只會找出還沒違約的。
也包含已違約（負值）。
官方來源
Agent 可以建立給團隊共用的 queue。
建立、編輯 queue 要 project admin。
官方來源
要分類 request 就用文字搜尋 summary ~ 建 queue。
官方建議用 request type、隱藏欄位或 automation 先分類。
官方來源

420.2.2 SLAs5 條

SLA 名稱之後可以改。
建立後不能改名。
官方來源
Work item 會同時符合多個 goal，取最短的。
由上而下第一個符合的 goal 生效。
官方來源
Priority 改變會讓 SLA 從頭計時。
已計時間會沿用到新目標。
官方來源
Pause condition 是必填。
Pause 是選填；start、stop 才是基本。
官方來源
新建的 SLA 只會套到之後建立的 work item。
會套到所有相關 work item，包含已關閉的。
官方來源

420.2.3 Features 開關5 條

Standard 方案也能用 change management 與 problem management。
2024/10/16 起只有 Premium／Enterprise。
官方來源
Services 可以在任何類型的 service project 開。
只有 ITSM project；Alerts、On-call 才是所有類型都能開。
官方來源
Feature lab 的功能一定會正式推出。
可能改變、可能不推出。
官方來源
降級到 Standard 會刪掉 change request。
資料不會遺失，request type 變 Unassigned、work item 移到 All queues。
官方來源
Alert priority 一定等於 incident priority。
可以不同；用 Assign alert priorities 對應。
官方來源

420.2.4 On-call5 條

Routing rules 會把所有符合的規則都套用。
只套第一個符合的，由上而下。
官方來源
把 alert route 到 schedule，沒人回應就會往上 escalate。
Route 到 schedule 只通知當下值班者，不會 escalate；要 escalation 就 route 到 escalation policy。
官方來源
Route 到 No one 會刪掉 alert。
Alert 會被記錄，只是不通知。
官方來源
Standard 方案可以設多條自訂 routing rule。
Free／Standard 只能 1 條；要多條需 Premium 以上。
官方來源
Team alert policy 優先於 global。
Global 先評估、同時符合時 global 優先。
官方來源

420.3.1 Assets5 條

Abstract object type 可以直接建立 object。
Abstract 型別不能放 object，只把 attributes 傳給 child。
官方來源
Object 的 Key 可以改。
Key 由 schema key＋數字組成，不能改。
官方來源
在 work item 加 object 只是單向記錄。
會建立雙向連結，object 頁看得到相關 work item。
官方來源
可以用 Assets object 欄位在 JQL 排序結果。
Cloud 不支援用 Assets object 欄位排序搜尋結果。
官方來源
Filter scope（AQL）可以用 ${reporter} 這類 placeholder。
Placeholder 只能用在 Filter work scope。
官方來源

420.3.2 Services5 條

Services 每個 service project 各自一份。
Service 是全站的，所有 service project 共用。
官方來源
Service type 會改變 service 的行為。
Type 只是分類標籤，沒有技術影響。
官方來源
把 Tier 1 service 加到 incident，priority 會自動變 Highest。
不會；要用 automation 依 tier 設 priority。
官方來源
把 service 加到 incident 會自動通知 owner team。
不會；要把 owner team 加成 responder。
官方來源
任何 service project 都能開 Services。
Services 只有 ITSM project；Alerts、On-call 才是任何類型都能開。
官方來源

420.3.3 Products 與 entitlements4 條

只有 Jira admin 能新增 product。
Admin 與 agent 都能新增、編輯 product；entitlement detail fields 才要 Jira admin。
官方來源
對 organization 建 entitlement 只影響建立當時的成員。
Entitlement 屬於 organization，所有成員都適用。
官方來源
要限制只有有 entitlement 的人提單，得寫 automation 擋。
把 Entitlement 欄位設成必填即可：沒有 entitlement 的人沒有選項。
官方來源
Entitlement detail fields 只出現在目前 project。
全站共用，套用到所有 product 與 customer。
官方來源

420.4.1 Request types5 條

一個 request type 可以同時對應兩個 issue type。
一次只能對一個；一個 issue type 可給多個 request type。
官方來源
要讓 request type 不出現在 portal，只能刪掉它。
從所有 portal group 移除即可。
官方來源
可以把 Reporter 或 Security level 放進 request form。
這兩個（以及 Issue type、Log work、Time tracking、Request participants）不能加到 request type。
官方來源
Request type 的 restriction 也會讓沒權限的人看不到已建立的 request。
只限制提單；要限制檢視用 issue security。
官方來源
Summary 這類必填系統欄位可以從 request form 移除。
不能移除或隱藏，只能改顯示名稱。
官方來源

420.4.2 Forms5 條

Form field 可以直接在 JQL 搜尋。
要先連到 Jira field。
官方來源
建 form field 要 Jira admin 建 custom field。
Form field 在表單裡直接建，只存在表單。
官方來源
Customer 用 email 提單也會看到附加的表單。
Forms 不支援 email、chat、widget、virtual agent。
官方來源
必填欄位可以放在條件 section 裡。
必填欄位（含連到 Summary 的）不能放在條件 section。
官方來源
編輯表單會更新所有已經附在 issue 上的表單。
不影響既有實例，也不影響複製到其他 project 的表單。
官方來源

420.4.3 Email requests5 條

Allowlist 可以加單一 email address。
Allowlist 只支援 domain；單一 email 只能加到 blocklist。
官方來源
加 example.com 到 allowlist 也會涵蓋 mail.example.com。
只做完全比對。
官方來源
在 allowlist 的 domain 一定收得到。
DMARC 驗證失敗仍會被過濾；同時在 blocklist 也會被擋。
官方來源
Email 用的 request type 可以加任意必填欄位。
只有 Summary、Description 可必填；否則 email 建不了 request。
官方來源
一個 service project 只能有一個 email address。
最多 10 個，每個可對應不同 request type。
官方來源

420.4.4 Workflows 與 approvals5 條

Approver 必須有 JSM agent 授權。
Customer 身分即可核准。
官方來源
Project admin 就能在 workflow 加 approval step。
要 Jira admin。
官方來源
任何 status 都能直接勾 Include approval step。
該 status 至少要有 Approve 與 Decline 兩個 transition。
官方來源
Customer 可以選一個 group 當 approver。
Customer 只能選個人；group 要用預設清單。
官方來源
每個 request type 都有自己的 workflow。
Workflow 跟著 issue type；共用 issue type 的 request type 共用 workflow。
官方來源

420.5.1 Customer portal4 條

Portal 的 banner 顏色在 Portal 設定頁改。
Portal 繼承 help center 的 URL、banner、按鈕與連結顏色，要改 help center。
官方來源
Agent 預設就能發 portal 公告。
要 project admin 勾 Yes, agents can add announcements。
官方來源
External resources 數量沒有限制。
最多 10 個。
官方來源
Portal logo 就是 project avatar。
兩者不同；logo 給 customer、也出現在通知信。
官方來源

420.5.2 Virtual agent5 條

Virtual agent 的 default request type 可以有必填欄位，virtual agent 會問 customer。
不能有必填欄位；virtual agent 無法填。
官方來源
Default request type 可以從 portal 隱藏。
不能隱藏：建立失敗時會給 customer 該表單的連結。
官方來源
Intent 可以用在 email 管道。
Intent 在 email 以外的 customer 管道可用。
官方來源
要關掉 Greet，得停用 virtual agent。
把 Greet 的 Message 留空就好。
官方來源
AI answers 不需要知識庫。
AI answers 是摘要連結的知識庫文章。
官方來源

420.5.3 通知與 canned responses5 條

Customer 關掉通知後就什麼都收不到。
仍會收到 resolved 與 approval required。
官方來源
Internal notifications 在 Customer notifications 頁設定。
Internal 走 Jira notification scheme（Jira admin）。
官方來源
Agent 是 reporter 又是 assignee 時兩種通知都收。
Internal 優先，只收 internal。
官方來源
Agent 可以建 shared canned response。
Agent 只能建 personal；shared 要 project admin。
官方來源
Canned response 建好後可以從 personal 改成 shared。
Availability 建立後不能改。
官方來源

420.6.1 知識庫連結與權限4 條

Unlink 會刪掉 Confluence space。
只從 service project 移除。
官方來源
Project admin 永遠可以把文章設成 Anyone。
要 site 層開 Anyone、Confluence 付費方案、portal 公開。
官方來源
在 KB 設定可以覆蓋 Confluence 的頁面限制。
頁面限制一定被尊重；進階權限要在 Confluence 改。
官方來源
All logged-in users 只包含 agent。
包含登入 help center 的 customer。
官方來源

420.6.2 知識庫內容3 條

Article suggestions 是整個 project 一個開關。
每個 request form 各自開。
官方來源
用 label 會把沒有 label 的文章從知識庫刪除。
只是不出現在該表單的推薦。
官方來源
知識庫連到其他 Confluence site 也會顯示推薦。
跨 site 時 portal 不顯示 article suggestions。
官方來源

420.7.1 JSM 的 JQL4 條

breached() 會找出所有曾經違約的 request。
breached() 只看最近一個 cycle；曾經違約用 everBreached()。
官方來源
approver(user) 只找還沒核准的。
approver() 不論是否已決定；還沒決定用 pendingBy()。
官方來源
paused() 會找出因為下班而沒計時的 request。
paused() 是條件造成的暫停；calendar 用 withinCalendarHours()。
官方來源
分享 filter 後，對方就能看到所有結果。
對方只看得到自己有 Browse 權限的 work item。
官方來源

Default reports 可以加 series。
Default 不能改；要用 custom report。

CSAT 問卷只有在 resolution 有值時才寄。
Status 進入 Done 類別就會寄，即使 resolution 沒設。

420.8.1 什麼時候用 automation3 條

所有通知需求都應該改用 automation。
固定事件通知用內建就好；automation 用在需要條件、特定收件人或提醒時。
官方來源
一次性改 500 張 request 最好寫 automation。
一次性用 bulk change。
官方來源
SLA 違約後才能觸發 automation。
SLA threshold breached 可設違約前或違約後的時間。
官方來源

420.8.2 設定 automation rule5 條

Object created trigger 可以用在 project rule。
Object trigger 只能用在 global rule。
官方來源
Attach forms 可以設定成 global rule。
Form 相關步驟只能在 project rule。
官方來源
Edit request type 可以換成任何 request type。
新 request type 要對應同一個 issue type，否則 audit log 出錯。
官方來源
一條 rule 可以有兩個 trigger。
只能一個；多個事件用 Multiple work item events trigger。
官方來源
Lookup objects 可以回傳無限多個 object。
最多 100 個。
官方來源

420.8.3 排查 automation5 條

Audit log 永久保存。
保留 90 天。
官方來源
No actions performed 代表 rule 壞了。
代表 condition 不符，rule 照設計停下。
官方來源
Owner 就是執行 rule 的帳號。
執行的是 actor；owner 收錯誤通知。
官方來源
Project admin 可以建跨多個 project 的 rule。
多 project 或 global scope 要 Jira admin。
官方來源
Transfer user 也會換掉 connection owner。
Connection owner 要手動改。
官方來源
